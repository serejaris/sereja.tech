Я подключил Claude Max к Hermes так, чтобы Opus в Telegram работал за счёт действующей подписки. Путь такой: официальный Claude Code авторизуется в аккаунте Max, Telegram Channel передаёт ему сообщения, рабочая папка остаётся у Hermes. Anthropic API key и Extra Usage для этой схемы не нужны.

На живом боте схема заработала с Opus в личке и в тредах. Extra Usage был выключен. Расход шёл по обычному лимиту Claude Max.

## Откуда берётся путаница

В настройках Hermes есть Anthropic OAuth. Кажется, что достаточно войти в аккаунт с Max и выбрать Opus. [Документация Hermes](https://hermes-agent.nousresearch.com/docs/integrations/providers) отдельно предупреждает: встроенный провайдер использует кредиты Extra Usage. Базовый лимит Max через него не расходуется.

Для пути через подписку нужен официальный рантайм Claude Code. Anthropic сейчас разрешает использовать `claude -p` и Agent SDK в пределах подписки. Компания [приостановила планировавшееся изменение биллинга](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan), поэтому схема продолжает работать с текущими лимитами Max.

## Как устроен путь через подписку

На сервере запускается авторизованный Claude Code. К нему подключается официальный Telegram-плагин Anthropic. Плагин принимает сообщение, передаёт его в живую сессию Claude Code и возвращает ответ в Telegram.

```text
Telegram → официальный Channel → Claude Code → Opus
                         │
                         └── файлы, скиллы и рабочая папка Hermes
```

У [Claude Code Channels](https://code.claude.com/docs/en/channels) двусторонняя связь. Можно написать боту с телефона, получить ответ, продолжить разговор в терминале и снова вернуться в Telegram. Для постоянной работы сессию нужно держать живой на сервере.

У меня модель `opus` разрешилась в `claude-opus-5`. Название конкретной версии со временем поменяется, поэтому в конфиге лучше просить актуальный Opus через официальный алиас.

Подключи мою действующую подписку Claude Max к Telegram-боту на этом сервере через официальный Claude Code Telegram Channel.

Сначала сделай резервную копию текущего конфига и сервиса Hermes. Проверь, что Claude Code установлен из официального источника и авторизован в моём аккаунте Anthropic. Выбери актуальный Opus.

Установи Bun и официальный Telegram-плагин `telegram@claude-plugins-official`. Возьми существующий токен бота из защищённого конфига, не печатай его в логах и ответах. Добавь мой Telegram user ID в allowlist. На одного бота оставь ровно один процесс polling.

Запусти канал как постоянный systemd user service с корректным PATH для Bun и Claude Code. Рабочей директорией оставь папку Hermes, чтобы Claude видел его инструкции, память и скиллы.

Проверь два сценария: ответ в личном сообщении и ответ внутри Telegram-треда через `reply_to`. Покажи только статусы тестов, выбранную модель и источник лимита. Если тесты не прошли, верни прежний сервис из резервной копии.

Во время авторизации Claude Code покажет ссылку или откроет браузер. Этот шаг лучше пройти самому: агенту не нужен пароль от Anthropic. Токен Telegram тоже стоит хранить в env-файле с закрытыми правами.

## Где чаще всего ломается

**Бот ставит реакцию и молчит.** Обычно входящее сообщение дошло, а ответ потерялся в шлюзе. Сначала смотрю журнал сервиса и проверяю, что Claude Code запущен в постоянной сессии.

**Личка работает, треды молчат.** Telegram ждёт ответ с привязкой к исходному сообщению. В шлюзе должен передаваться `reply_to`. Это был отдельный тест в моей проверке.

**Telegram пишет конфликт polling.** Один токен одновременно слушают два процесса. Старый Hermes-шлюз и новый Channel начинают отбирать события друг у друга. На время переключения оставляю одного слушателя.

**Сервис работает из терминала и падает после перезапуска.** У systemd может быть другой `PATH`. В нём должны находиться Bun и Claude Code. Полезно перезагрузить сервис и сервер, затем повторить тест.

**Claude отвечает без памяти Hermes.** Проверь рабочую директорию процесса. Именно там должны лежать инструкции, скиллы и файлы контекста. Я отдельно попросил агента сохранить эту папку при миграции.

## Как понять, что всё подключилось

Я проверяю четыре вещи:

1. `claude` видит активную авторизацию Max.
2. Алиас `opus` выбирает актуальную модель Opus.
3. Бот отвечает в обычном сообщении и внутри треда.
4. В аккаунте Anthropic Extra Usage остаётся выключенным.

После этого отправляю реальную задачу с доступом к файлам Hermes. Простой ответ «привет» проверяет только Telegram. Запрос вроде «прочитай свои инструкции и назови доступные скиллы» подтверждает, что рабочий контекст тоже на месте.

У лимита Max остаются обычные ограничения Anthropic. При большой нагрузке Claude Code может попросить дождаться сброса окна. Сервер использует уже действующую подписку, отдельный API-баланс не требуется.

## Что в итоге

Чтобы использовать обычный лимит Claude Max, я запускаю официальный Claude Code с Telegram Channel в рабочей папке Hermes. Hermes сохраняет инструкции, память и скиллы. Claude Code даёт Opus и списывает запросы с подписочного лимита.

В моём случае переход занял одну агентскую задачу. Бот живёт на сервере, отвечает с Opus, видит скиллы Hermes и поддерживает треды. Главная проверка была простой: Extra Usage выключен, ответы продолжают приходить.

## Частые вопросы

### Можно подключить Max прямо через `hermes setup`?

Можно авторизовать Anthropic OAuth, при этом Hermes будет расходовать Extra Usage. Для базового лимита Max нужен путь через Claude Code.

### Нужен отдельный Anthropic API-ключ?

Для схемы с Claude Code Telegram Channel ключ не нужен. Достаточно активной авторизации Claude Max в официальном CLI.

### Бот будет работать после закрытия SSH?

Да, если Claude Code и Telegram Channel запущены как постоянный сервис или в другой живой серверной сессии. Обычный процесс в SSH завершится вместе с терминалом.

### Можно оставить старого Telegram-бота?

Да. Его токен можно передать официальному Channel. Перед запуском стоит остановить прежний polling-процесс, чтобы два шлюза не читали одного бота одновременно.
