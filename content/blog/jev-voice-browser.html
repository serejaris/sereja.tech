Как Jev выбирает действие по голосовой команде

Человек говорит "нажми Документация". Браузер распознаёт речь, Jev выбирает подходящий пункт, код нажимает кнопку. Этот короткий путь показывает, где модель помогает программе принять решение и что остаётся ответственностью программы.

Что показывает голосовой браузер

В demo Moritz Kremb человек голосом открывает Wikipedia, выбирает English и возвращается назад. Рядом со страницей находится пульт: распознанная команда, решения Jev и журнал действий. Такой интерфейс позволяет видеть связь между фразой, выбором модели и изменением страницы.

Открытая реализация этого подхода: Voice Browser с открытым кодом: пульт, учебную страницу и расширение Chrome. Инструкция запуска находится в README репозитория. Для настоящей Jev нужен собственный ключ Gateway; режим локальных правил отдельно выполняет ограниченные команды без модели и вероятностей.

В проверке открытой реализации Voice Browser через настоящую Jev выполнены действия по текстовым командам. В установленном расширении отдельно наблюдалось распознавание русской речи после включения микрофона пользователем. Полная цепочка от живой речи до выполненного действия ещё не подтверждена.

Из чего складывается запрос Jev

Jev относится к моделям типизированных решений. Программа задаёт форму ответа заранее: выбор из вариантов, положение на шкале или вероятность yes/no. Модель оценивает ситуацию и возвращает значения этой формы. Свободный текст полезен для объяснения человеку. Типизированное решение передаёт программе готовое значение для следующего шага. Подробнее о классе моделей и релизе: "TypeSafe выпустила Jev для быстрых решений в программах".

Представьте сотрудника, который получает заявку и перечень доступных операций. Ему нужно выбрать подходящий пункт, затем система исполняет операцию. В браузерном пульте Jev занимает место такого выбора. Список операций готовит код по текущей странице.

У запроса две части: state и questions. Состояние state описывает ситуацию. Здесь это команда пользователя, заголовок страницы и краткий список видимых элементов. DOM, структура страницы с кнопками, ссылками и полями, служит источником списка. Каждый элемент имеет короткий идентификатор, подпись и тип.

В questions программа задаёт вопрос о действии. Тип choice означает выбор одного пункта. Поле instructions объясняет задачу, а criteria связывает идентификаторы вариантов с описаниями. Для команды "нажми Документация" возможны пункты "Документация", "назад", "прокрутить вниз" и "ничего не делать".

Такой запрос содержит описание страницы и ограниченный набор действий. Локальный сервер передаёт его в typesafe-ai/jev через AI Gateway. Пульт инструктирует Jev считать текст страницы данными для оценки. Полученный ответ всё равно проходит проверки кода. В запросе этой реализации изображение страницы отсутствует: Jev выбирает по текстовым подписям элементов.

Для новой страницы важно проверить доступность элементов. Кнопка без понятной подписи или элемент canvas может отсутствовать среди вариантов; перефразирование команды само по себе не добавит нужную операцию. Разделение работы модели и кода также разобрано в статье о Structured Output. Здесь форма выбора особенно компактна: код получает идентификатор подготовленной операции.

Что означают вероятности

Ответ choice содержит выбранный вариант и распределение вероятностей по вариантам. Оно показывает оценку модели для подготовленного набора. Эти значения можно использовать в программе: например, выполнить действие при достаточной вероятности и заметном отрыве от второго пункта.

У TypeSafe есть отдельное поле confidence, характеризующее форму распределения. Вероятность конкретного пункта и confidence являются разными полями API. Пульт Voice Browser показывает вероятности вариантов и использует их для проверки перед исполнением.

В проверке Voice Browser "Документация" получила 98%. Показатель решения составил 555 мс, действия 2 мс. "Решение" включает сбор элементов, сетевой запрос и проверку ответа. "Действие" измеряет вызов исполнения без ожидания полной загрузки новой страницы. Время окончания голосовой фразы сюда не входит.

В проверке Voice Browser расширение выбрало English на Wikipedia с вероятностью 96%: 611 мс на решение и 30 мс на действие. Скорость зависит от сети, нагрузки и страницы. Несколько таких попыток не дают средней задержки или гарантии надёжности.

Кто решает, выполнять ли действие

Код сопоставляет выбранный идентификатор с заранее подготовленной операцией. Ответ модели проходит проверку: вариант входит в список, вероятности допустимы, команда всё ещё актуальна. В пульте Voice Browser действует порог 65% и отрыв минимум 10 процентных пунктов с поправкой на округление ответа.

Пока идёт запрос, пользователь может отменить команду или отправить новую. Старый ответ после этого теряет право на исполнение. Перед кликом пульт заново проверяет документ и элемент, включая подпись и тип. Такая проверка важна, если страница успела измениться.

Вариант none, "ничего не делать", даёт модели возможность остановиться. Пороги тоже могут остановить действие. Это условия приложения; выбранный пункт всё равно может оказаться ошибочным.

В этом прогоне человек просил ввести текст в доступное поле, но Jev предпочла остановиться. Это ошибочный отказ, при более ранней проверке ввод выполнился. Вероятности помогают увидеть причину остановки. Они не доказывают, что решение модели верно.

Клики с признаками отправки, оплаты или удаления требуют подтверждения человека в пульте. Проверка по подписи и типу имеет ограничения. Необычно названная операция может пройти без такого подтверждения. Последствия конкретного сайта нужно оценивать отдельно.

Где проходит граница применения

В этой архитектуре распознавание отвечает за текст команды, Jev за выбор, программа за допустимые действия и исполнение. Модель не получает права выполнять произвольный код. Для ввода пульт использует дословный текст команды: например, слова после "введи".

Доступ расширения Chrome связан с выбранной пользователем страницей. При переходе на другой домен временный activeTab может закончиться. Дополнительный доступ к текущему сайту запрашивается явно. Внутренние страницы Chrome, закрытые Shadow DOM и сторонние вложенные iframe текущая реализация не поддерживает.

В облачный запрос уходят команда, заголовок и подписи элементов. Значения полей и пароли пульт не собирает, но сами подписи могут содержать личную информацию. Ключ Gateway остаётся на локальном сервере. Распознавание речи Chrome также может использовать удалённый сервис.

Подход переносится на небольшой пульт каталога или переключение разделов справочника во время созвона. Это возможные сценарии, не заявленные внедрения. Хорошая исходная задача содержит ясные подписи, ограниченный набор операций и проверяемый результат. Каждое новое приложение требует собственной проверки.

Для повторения опыта начните с учебной страницы из репозитория. Посмотрите на выполненную команду, затем на ошибочный отказ и отмену ожидающего запроса. Эти наблюдения показывают, как решение Jev становится действием и где программа должна его остановить.
